Objective: a repair task file declares why the repair is needed, as `cause: worker|contract|environment|verify` plus an optional one-line `causeNote:`. zc records both in result.json as `repairCause`. `zc dispatch --repair` refuses a task without a valid `cause`. Also add one regression test for chained repairs, the gap left by the T-018 review.

Root cause (verified 2026-11-15 from source):
- src/task.mjs:57-73 (`parseTask`) keeps only `id`, `title`, `allowed`, `verify`, `ecc`, `minutes` and `model`, so any other front-matter key is dropped.
- src/dispatch.mjs:94-98: the result records `repairOf` but no reason for the repair.
- .zc/tasks/T-015.md:61 and :101: repair causes exist only as free text in task files, which blocks any repair-rate attribution.

Decisions (final):
1. src/task.mjs:
   - Export `export const REPAIR_CAUSES = ['worker', 'contract', 'environment', 'verify'];`, with a one-line JSDoc giving the meanings:
     - `worker`: the worker did not follow the contract, or its code is wrong.
     - `contract`: the manager's contract was wrong or incomplete.
     - `environment`: tooling, fixtures, accounts or the machine.
     - `verify`: a verify command itself was wrong or flaky.
   - In `parseTask`, add two fields to the returned `meta`, after `model`:
     - `cause`: `undefined` if the key is absent. Otherwise `String(meta.cause).trim().toLowerCase()`. If the raw value is an array (an empty `cause:` line parses as `[]`), or the normalized value is not in `REPAIR_CAUSES`, throw `Error('task cause must be one of worker, contract, environment, verify')`.
     - `causeNote`: `undefined` if absent. Otherwise `String(meta.causeNote).trim()`, cut to 300 characters. An empty string becomes `undefined`.
   - A task without these keys parses exactly as now, apart from two extra `undefined` fields.
2. src/dispatch.mjs, initial `result` (:94-98): add `repairCause` directly after `repairOf`. Its value is `repairOf ? { kind: task.meta.cause ?? null, note: task.meta.causeNote ?? null } : null`. Nothing else in dispatch changes. In particular, `dispatch()` itself does not refuse a missing cause, so library callers and the existing tests keep working.
3. src/cli.mjs, `cmdDispatch` (:166-181): right after `const task = readTask(opts, root);`, if `opts.repair` and `!task.meta.cause`, throw `Error('a repair task must declare its cause in front matter: cause: worker|contract|environment|verify (optional causeNote: <one line>)')`. This fires before `dispatch` is called, so no run folder is created. `main` already prints `zc: <message>` and returns 3.
   - Help text (src/cli.mjs:22): change `send feedback on top of a worker's uncommitted result` to `send feedback on top of a worker's uncommitted result (task declares cause:)`, keeping the alignment.
4. skills/orchestrate/SKILL.md:47 (the Repair step): after `in the same contract form,` insert `with \`cause:\` (worker, contract, environment or verify) and a one-line \`causeNote:\` in the front matter,`. Change nothing else in the file.
5. docs/ARCHITECTURE.md:28: append the sentence `A repair run also records repairCause ({ kind, note }) from the repair task's cause and causeNote front matter; zc dispatch --repair refuses a task without a valid cause.` Format the field names and the command as code.
6. CHANGELOG.md, under `## [Unreleased]` → `### Added`, after the existing bullet:
   ```
   - Repair tasks declare why the repair is needed: `cause: worker|contract|environment|verify` and an optional one-line `causeNote:` in front matter. They are recorded in `result.json` as `repairCause`. `zc dispatch --repair` refuses a task without a valid `cause`.
   ```
