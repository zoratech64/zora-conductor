Objective: every group in the output of `node scripts/measure.mjs runs` gains a `repairCauses` object. It counts that group's repair runs by `repairCause.kind`, with the repair runs that have no recorded cause counted separately, so repair rates can be attributed to worker, contract, environment or verify.

Root cause (verified 2026-11-15 from source):
- scripts/measure.mjs:170-252 (`summarizeGroup`) counts `repairRuns` from `repairOf` (:194-196) but never reads `repairCause`.
- src/dispatch.mjs:96 has recorded `repairCause: { kind, note }` on repair runs since T-019 (`kind` may be `null` for library callers). src/task.mjs:54 exports `REPAIR_CAUSES = ['worker', 'contract', 'environment', 'verify']`.
- Runs recorded before T-019 have no `repairCause` key.

Decisions (final):
1. scripts/measure.mjs:
   - Extend the existing import line to `import { parseTask, REPAIR_CAUSES } from '../src/task.mjs';`. Do not copy the list.
   - In `summarizeGroup`, build `repairCauses` with one key per entry of `REPAIR_CAUSES`, in that order, each starting at `0`, then `unrecorded: 0` last. All five keys are always present, even when the group has no runs.
   - Inside the existing `if (r.repairOf != null && r.repairOf !== '')` block, and only there: if `r.repairCause` is a plain object (use `isPlainObject`) whose `kind` is a string in `REPAIR_CAUSES`, increment that key. Otherwise (key missing, `null`, `kind` null, or an unknown or non-string kind) increment `unrecorded`. Do not normalize case: zc writes lowercase kinds.
   - A `repairCause` on a run without `repairOf` is ignored.
   - Invariant: the five counts always add up to `repairRuns`.
   - Return `repairCauses` directly after `repairRuns` in the group object. Key order: `runs, statuses, repairRuns, repairCauses, attempts, metrics`.
   - Append to `RUN_REPORT_NOTES`: `'repairCauses.unrecorded counts repair runs with no valid repairCause.kind, such as runs recorded before repair causes existed.'`
   - Change nothing else: not `collectRunRecords`, the split logic, `metrics`, `measurePrompts`, `compare` or `selectPromptSection`, and not the USAGE text or any CLI branch.
2. docs/ARCHITECTURE.md:92: after `` `runs` aggregates metrics across recorded run results`` insert ``, including repair counts by `repairCause.kind` (`repairCauses`)``. Change nothing else in the file.
3. CHANGELOG.md, under `## [Unreleased]` → `### Added`, append after the last existing bullet:
   ```
   - `scripts/measure.mjs runs` reports `repairCauses` per group: repair runs counted by `repairCause.kind` (`worker`, `contract`, `environment`, `verify`), with repair runs that have no recorded cause counted as `unrecorded`.
   ```
