Objective: add `zc accept [<runId>]`, which stages only the files a verified worker run produced, so the manager never needs `git add -A`. It never commits.

Decisions (final, do not reopen):
1. src/dispatch.mjs: new exported `acceptRun({ root, runId })`, placed after `rejectRun` and modelled on it (same lock: `acquireLock(lockFile(root), { runId: \`accept-${prev.runId}\` })`, released in `finally`). Steps, each failing closed with `throw new Error(<clear message naming the run and paths>)` and staging nothing:
   a. `prev = runId ? getRun(root, runId) : listRuns(root, 1)[0]`; none -> error `no run to accept (see \`zc runs\`)`.
   b. `prev.status !== 'OK'` -> error: only a verified (OK) run can be accepted.
   c. `!prev.workerState` -> error: no recorded file contents.
   d. `G.head(root) !== prev.head` -> error: HEAD moved since the run.
   e. `current = G.dirtyState(root)`. `owned = Object.keys(prev.workerState)`. Any owned path whose `current[p] !== prev.workerState[p]` (changed, staged, reverted or missing since the run) -> error listing those paths (ambiguous ownership).
   f. Paths in `current` but not in `owned` are NOT the run's: never stage or modify them; return them as `leftAlone`.
   g. Stage owned paths with `G.git(root, ['--literal-pathspecs', 'add', '-A', '--', ...batch])` in batches of 100 (`-A` limited by the pathspec records deletions and both sides of renames; `--literal-pathspecs` stops glob interpretation). `.zc/` paths are never in workerState (dirtyState excludes them).
   h. Return `{ runId: prev.runId, staged: owned.sort(), leftAlone: <sorted> }`. No commit.
   Note: a run's tree was clean at dispatch (or matched the run it repaired), so every path in `workerState` was produced by the worker chain; that is the ownership proof.
2. Change the OK `nextAction` in `dispatch` to: 'review `git diff` yourself, run your own checks, then `zc accept <runId>` (stages only this run\'s files) and commit; or send a repair / reject.' Check existing tests for this exact string before changing it; update none unless they assert it (if one does, report it instead of editing that test).
3. src/cli.mjs: add `case 'accept'` next to `case 'reject'`: `acceptRun({ root: projectRoot(opts), runId: opts._[0] })`; print `zc: staged <n> file(s) from run <id>` then each path indented, and if `leftAlone.length` a line `left alone (not this run's): <paths>`; return 0. Errors propagate like reject's (same top-level handling). Add help line under `zc reject`: `  zc accept [<runId>]                     stage only a verified run's files (never commits)`. Import `acceptRun`.
4. Docs: docs/ARCHITECTURE.md one bullet near "Staged changes count": `zc accept` stages exactly the run's recorded paths after checking status OK, unchanged HEAD and unchanged contents; anything else is left alone; any mismatch stages nothing. README.md: add the `zc accept` line wherever `zc reject` is listed in a command list (if any).
