Objective: after the verify commands run, re-check `.zc/`, HEAD/branch and repository scope exactly as zc already does after the worker, so nothing changed during verify can end a run as OK. Source: docs/audits/ZC-HARDENING-SPEC.md, task ZCH-001 (read only that section; do not edit the spec).

Decisions (final, do not reopen):
- All changes are inside the `if (succeeded) { ... }` block of `dispatch()` in src/dispatch.mjs, between the existing `runVerify(...)` call (about line 279) and the existing `VERIFY_FAILED` / `OK` returns. Do not touch any other branch, the attempt loop, the failure path, `rejectRun`, or any other src file.
- Right after `result.verifyDurationMs` is set and BEFORE the `VERIFY_FAILED` check, run these post-verify checks in this order (they run whether verify passed or failed):
  1. `.zc/` re-check: `const verifyZc = restoreZc(root, zcSnap, { saveDir: join(runDir, \`zc-violations-verify-${n}\`) });` wrapped in try/catch exactly like the existing worker-phase call (about line 209): on throw set `attempt.outcome = 'zc-not-checked'` and `return finish('NEEDS_HUMAN', EXIT.NEEDS_HUMAN, { account: account.id, phase: 'verify', nextAction })` where nextAction says `.zc/` could not be read after verify, nothing was rolled back, and names `zc-snapshot-${n}`. If any entry has `restored === false`: `attempt.outcome = 'zc-not-restored'`, `return finish('NEEDS_HUMAN', ...)` with `phase: 'verify'`, `forbidden` = those paths, and a nextAction naming `zc-violations-verify-${n}` and `zc-snapshot-${n}`. If entries exist, also set `attempt.zcViolationsVerify = verifyZc`.
  2. HEAD/branch re-check: `if (G.head(root) !== head0 || G.branch(root) !== branch0)` → `attempt.outcome = 'moved-head'` and `return finish('NEEDS_HUMAN', EXIT.NEEDS_HUMAN, { account: account.id, phase: 'verify', nextAction: 'a verify command moved HEAD or switched branches. Nothing was rolled back automatically; inspect with \`git reflog\`.' })`.
  3. Scope re-check: `const postEntries = G.statusEntries(root); const verifyChanged = G.changedPaths(postEntries).filter((p) => !changed.includes(p)); const vScope = partitionByScope(verifyChanged, allowed, config.forbidden); const vZcPaths = verifyZc.map((v) => v.path);`
- If `vScope.forbidden.length || vScope.outOfScope.length || vZcPaths.length`: `G.savePartial(root, join(runDir, 'rejected-verify'), postEntries);` then `const rolledBack = resetAllowed && G.rollbackPaths(root, postEntries, G.dirtyState(root)).conflicts.length === 0;` then `return finish('SCOPE_VIOLATION', EXIT.FAILED, { phase: 'verify', verifyChanged, outOfScope: vScope.outOfScope, forbidden: [...vScope.forbidden, ...vZcPaths], rolledBack, nextAction })`. nextAction (rolled back): 'a verify command changed files outside the allowed paths (or .zc/); the whole result was saved to the run folder and rolled back. If your build or tests legitimately write these files, add them to `allowed` or .gitignore.' nextAction (not rolled back): same first clause, then 'the tree was left as-is. Review with `git status`, then `zc reject`.' This rolls back the whole result (worker work included), exactly like the existing worker-phase SCOPE_VIOLATION. This return takes precedence over VERIFY_FAILED.
- Otherwise, if `verifyChanged.length`, set `result.verifyChanged = verifyChanged` and `result.changed = [...new Set([...changed, ...verifyChanged])].sort()`. Then the existing VERIFY_FAILED / OK logic continues unchanged.
- In the existing worker-phase SCOPE_VIOLATION `finish(...)` call add `phase: 'worker'` and nothing else.
- In `formatResult`, change the first line only when `r.phase === 'verify'`: append ` during verify` after the status, e.g. `zc: run X -> SCOPE_VIOLATION during verify (exit 1)`. Everything else in formatResult stays as is.
- `restoreZc` and `partitionByScope` are already imported in dispatch.mjs; add no imports unless one is genuinely missing.
