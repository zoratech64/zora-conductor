Objective: the project's `verify` commands in .zc/config.json are mandatory for every dispatch. A task's `verify:` (and CLI `--verify`) adds checks; it can never remove or replace project checks.

Current behavior (confirmed): src/dispatch.mjs `taskPrompt` line ~42: `const verify = task.meta.verify.length ? task.meta.verify : config.verify;` so a task with `verify: [true]` runs only `true` and skips `npm test`.

Decisions (final):
1. In `taskPrompt`, replace that line with: effective verify = `config.verify` first (in order), then each task command whose `argv.join(' ')` is not already present (dedupe exact duplicates, keep first occurrence, keep task order). Extract this as an exported pure helper `effectiveVerify(projectVerify, taskVerify)` in src/dispatch.mjs, returning a new array (do not mutate inputs).
2. No opt-out: no new config key, task field or flag. Empty/missing task verify = project verify only (as today).
3. Record the effective set: in `dispatch`, set `result.verifyPlan = verifyCmds.map((argv) => argv.join(' '))` next to where `result.eccRules` is set (new optional field). `result.verify` (executed results, stops at first failure) is unchanged.
4. Everything else unchanged: the prompt's "Completion gates" list now naturally shows the effective set; `runVerify` unchanged; exit codes unchanged.
5. docs/ARCHITECTURE.md: add one bullet (in the section about verification/safety, or near the existing staged-changes bullet ~line 75) stating: project `verify` always runs; task `verify` only adds commands; `result.json` `verifyPlan` lists the effective set. CHANGELOG.md [Unreleased]: add a `### Fixed` section above `### Changed` (if none exists) with one bullet: a task's `verify:` no longer replaces the project's verify commands; it adds to them (marked **Breaking** for task files that relied on replacing).
