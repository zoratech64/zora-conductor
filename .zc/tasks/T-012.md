title: Fix two CLI smoke tests that fail when the temp dir path is not canonical (Windows, macOS)
allowed:

Root cause (proven): `projectKey(root)` hashes the path. Both CLI smoke tests in test/accept.test.mjs dispatch in-process with `root: dir` (the raw `mkdtempSync` path) but then run `node bin/zc.mjs accept` in a child process, which resolves the project root with `toplevel(cwd)` (git `rev-parse --show-toplevel`, canonical). On macOS `/var/...` vs `/private/var/...` and on Windows 8.3 short names or case/slash differences, the two spellings give different run folders, so the CLI prints `zc: no run to accept`. It is a test-setup bug; src/ is correct (real users always go through the CLI).

Reproduce on Linux: `S=<any dir>; mkdir $S/real; ln -sfn $S/real $S/link; TMPDIR=$S/link npm test` fails exactly these two tests:
- `CLI smoke: node bin/zc.mjs accept <runId> in temp repo exits 0 and prints staged`
- `CLI smoke: accept refuses when an unrelated file was already staged and leaves index unchanged`

Decisions (final):
1. In test/accept.test.mjs add `import { toplevel } from '../src/gitx.mjs';`.
2. In exactly those two tests, compute `const root = toplevel(dir);` right after `makeRepo()` and use `root` instead of `dir` for the `dispatch({ root, ... })` call. Use the same `root` as the child's `cwd`. Keep `git(dir, ...)` calls and `writeFileSync(join(dir, ...))` as they are (same folder). Do not change any assertion.
3. Do not change any other test, helpers.mjs, or anything under src/.
4. Do not skip, weaken or delete any test or assertion.

Done when: `npm test` passes normally AND passes with a symlinked TMPDIR as described above (run it once that way and include the pass count in your report), and `npm run check` passes.

If blocked: report the contradiction with file:line.

Verification: npm test, npm run check.
