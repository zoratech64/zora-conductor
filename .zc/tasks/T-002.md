Decisions (final, do not reopen):
1. Template source. `zc init` currently writes the task template inline in `cmdInit` (src/cli.mjs ~line 68, a `[...].join('\n')` array). Move that text into a new `src/template.mjs` exporting `TASK_TEMPLATE` (a string ending in a newline) and make `cmdInit` write `TASK_TEMPLATE`. Front matter lines stay exactly as today (id T-001, title, allowed, verify, minutes, commented ecc lines). Replace only the body with this (use this text verbatim):
```
Objective: one sentence.

Decisions (final; the worker does not reopen them): approach, names, patterns, behavior.

Per file:
- path/to/file: what to change (symbols, line anchors) and the expected result.

Read first: files the worker must read besides the ones it edits (keep short).

Do not: files, behavior or refactors that are out of scope.

Done when: observable acceptance criteria and tests.

If blocked: report the contradiction or missing dependency with file and line evidence; do not guess or widen scope.

Verification: the manager (zc) runs the verify commands above; the worker cannot run commands.
```
   Do not touch any existing project's `.zc/` files (zc init refuses to overwrite config; keep that behavior).
2. Worker prefix (src/prompt.mjs). Keep the existing `DEFAULT_PREFIX` template literal text byte-for-byte but rename the constant to `PREVIOUS_PREFIX` (not exported). Add a new non-exported constant `CONTRACT_RULES` with exactly this text:
```
## Working from the manager's contract
- The task's decisions (approach, names, files, behavior) were made by the manager and are authoritative. Do not redesign or reopen them.
- Read every file you will edit before editing it. Beyond those, read only files the task names and the direct imports or callers you need in order to edit safely. Do not explore the rest of the repository.
- If the task contradicts the code (a missing symbol, a wrong signature, an impossible instruction) or a file you need is not allowed, do not guess and do not widen scope. Do the parts that are sound and report the contradiction with file and line evidence.
- Never change the architecture or touch files outside the allowed paths on your own.
```
   Then `export const DEFAULT_PREFIX = \`${PREVIOUS_PREFIX}\n\n${CONTRACT_RULES}\`;`. Every existing safety line stays in `PREVIOUS_PREFIX` unchanged.
   Legacy handling: a project's frozen `.zc/worker-prefix.md` that equals an older default must keep following the current default. Make `LEGACY_PREFIXES` = `[PREVIOUS_PREFIX, PREVIOUS_PREFIX minus the NO_COMMANDS_LINE line, DEFAULT_PREFIX minus the NO_COMMANDS_LINE line]`, each `.trim()`med (the third keeps the existing test in test/ecc.test.mjs passing). `NO_COMMANDS_LINE` is declared after `DEFAULT_PREFIX` today; reorder declarations so nothing is used before it is defined. `loadPrefix` logic is unchanged.
