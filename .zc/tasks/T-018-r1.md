Objective: a repair may inherit only paths that the repaired run's own scope check covered, which are the paths in `prev.changed`. Files that the repaired run's verify commands created or changed are never inherited, so the repair's `allowed` check covers them as before. Keep the rest of your earlier T-018 work as it is.

Cause (verified 2026-11-15, reproduced by the manager):
- src/dispatch.mjs:148 sets `baseline = prev.workerState`. `finish()` (src/dispatch.mjs:103) records `workerState` at finish time, after verify ran (src/dispatch.mjs:318-327). The scope check at src/dispatch.mjs:287 ran before verify, and `prev.changed` holds only the paths it checked.
- So the inherited filter at src/dispatch.mjs:293 also exempts files written by verify, which no check ever covered.
- Reproduction: first run `allowed: [src/]`, fake writes `src/a.txt`, verify writes `other/gen.txt` and exits 1, so VERIFY_FAILED with `changed` `['src/a.txt']` and `workerState` keys `['other/gen.txt', 'src/a.txt']`. A repair with `allowed: [test/]` that writes `test/b.txt` ends OK with `inherited` `['other/gen.txt', 'src/a.txt']`, and `acceptRun` stages `other/gen.txt`. Before T-018 this was reported as out of scope.
- The flaw was in the T-018 contract (decision 2 used `prev.workerState` alone), not in how you implemented it.

Decisions (final):
1. src/dispatch.mjs, in the `if (repairOf)` block: next to `baseline = prev.workerState;`, record `prevChanged = new Set(prev.changed ?? []);`. Declare it with `let prevChanged = new Set();` beside `inheritable` and `baseline`.
2. src/dispatch.mjs:293: the inherited filter becomes
   `changed.filter((p) => prevChanged.has(p) && Object.hasOwn(baseline, p) && workerState[p] === baseline[p]).sort()`.
   Nothing else in the scope check changes.
3. `acceptRun` stays as it is. It already relies on `prev.inherited`, which now holds only scope-checked paths.
4. A repair of a repair still chains: a repair's `changed` contains its inherited paths, and they passed its check.
5. docs/ARCHITECTURE.md, in the bullet you added after :34: change `files the repaired run changed (if that run was OK or VERIFY_FAILED)` to `files the repaired run's worker changed and zc scope-checked (if that run was OK or VERIFY_FAILED; files its verify commands wrote are not included)`. Leave the rest of the bullet as is.
6. CHANGELOG.md, in the `### Fixed` bullet you added: change `over files that run changed and the repair left untouched` to `over files that run's worker changed within its scope and the repair left untouched`. Leave the rest of it as is.
