Objective: fix safety gaps an independent audit found in `acceptRun` (src/dispatch.mjs, added in T-006) plus two small inaccuracies. No other behavior changes.

Findings and decisions (final):
1. HIGH - accept can stage files outside the task scope. `finish()` records `result.workerState = G.dirtyState(root)` after `runVerify`, so files a verify command writes (build output, formatter rewrites) are in `workerState` without ever being scope-checked; `acceptRun` stages every `workerState` key.
   Fix: change the signature to `acceptRun({ root, runId, config })`. After the existing checks (status OK, workerState, HEAD, fingerprints) and before staging: compute `scope = partitionByScope(owned, prev.allowed ?? [], config.forbidden)` (src/scope.mjs, already imported in dispatch.mjs) and `notChanged = owned.filter((p) => !(prev.changed ?? []).includes(p))`. First confirm by reading `dispatch` that an OK result's `changed` lists the worker's changed paths (it is set at the scope check); if it does not, report that instead of using it. If `scope.outOfScope`, `scope.forbidden` or `notChanged` is non-empty, throw (stage nothing) with a message naming those paths, e.g. `cannot accept run <id>: paths outside the task scope or not checked as the worker's change: <paths>. Review them, then stage by hand or zc reject.`
   src/cli.mjs `case 'accept'`: pass `config: loadConfig(root)` (loadConfig is already imported; compute root once with `projectRoot(opts)`).
2. MEDIUM - partial staging on error. Batches of `git add` can leave earlier batches staged if a later one fails.
   Fix: stage in ONE git call reading paths from stdin: `G.git(root, ['--literal-pathspecs', 'add', '-A', '--pathspec-from-file=-', '--pathspec-file-nul'], { input: owned.join('\0') })`. In src/gitx.mjs `git()`, add an optional `input` option passed to `spawnSync` (`input` key) - no other change to `git()`. Remove the batching loop. Skip the call when `owned` is empty.
3. LOW - unrelated paths the user already staged would be swept into the next `git commit`. Fix: return an extra field `alreadyStaged`: the sorted subset of `leftAlone` that has a staged (index) change, computed from `G.statusEntries(root)` before staging (an entry whose `xy[0]` is not ' ' and not '?'). CLI prints, when non-empty: `warning: already staged and not this run's (a commit would include them): <paths>`.
4. LOW - src/fsx.mjs line ~50 lock message: change `(dispatch or reject)` to `(dispatch, reject or accept)`.
5. LOW - `effectiveVerify` dedupe key `argv.join(' ')` treats `["npm test"]` as a duplicate of `["npm","test"]`. Use `JSON.stringify(argv)` as the key for both seen-set and lookup.
6. docs/ARCHITECTURE.md: in the existing `zc accept` bullet, add: it also refuses paths outside the task's `allowed`, forbidden paths, and paths not recorded as the worker's change (e.g. files written by verify commands); staging is a single all-or-nothing git call; it cannot stop edits made by other programs between its check and the stage.
