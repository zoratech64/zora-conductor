Objective: `node scripts/measure.mjs compare --key <name> <pre.json> <post.json>` compares the `prompt-size` objects stored under top-level key `<name>` in each file. Without `--key`, `compare` behaves exactly as it does now.

Root cause (verified 2026-11-15 from source and the stored files):
- scripts/measure.mjs:311-313: `comparePromptSizes(pre, post)` throws `both arguments must have kind: "prompt-size"` unless both top-level objects are `prompt-size`.
- scripts/measure.mjs:469-494 (CLI `compare`): reads both files and passes the parsed top-level objects straight in. `parseArgs` (src/args.mjs) accepts any `--flag value`, so a `--key` today is parsed and silently ignored.
- `.zc/baseline-pre.json` and `.zc/measure-post.json` are combined files: their `prompt-size` objects sit under `promptConfigPacks` and `promptCommonDart`. So `node scripts/measure.mjs compare .zc/baseline-pre.json .zc/measure-post.json` exits 1 (recorded in .zc/tasks/T-015.md:18; follow-up listed at T-015.md:100).
- Probe: `comparePromptSizes(pre[k], post[k])` for both keys gives output that deep-equals `.zc/measure-phase1-runs.json` `compare[k]`. Only the CLI cannot reach those sections.

Decisions (final):
1. scripts/measure.mjs: add an exported pure function, placed directly above `comparePromptSizes`:
   ```js
   export function selectPromptSection(doc, key, label) { ... }
   ```
   - `key === undefined`: return `doc` unchanged. `comparePromptSizes` keeps doing the kind check, with its message unchanged.
   - `key` is not a non-empty string: throw `Error('--key needs a value')`.
   - `doc` is not a plain object (use the existing `isPlainObject`), or `!Object.hasOwn(doc, key)`: throw `Error(\`${label} has no "${key}" section\`)`.
   - Otherwise return `doc[key]`. Do not check its kind here; `comparePromptSizes` does that.
   - `label` is the file path exactly as typed on the command line.
2. CLI `compare` branch (scripts/measure.mjs:469-494):
   - After parsing both files: `const pre = selectPromptSection(JSON.parse(preText), opts.key, prePath);` and the same for post with `postPath`. Errors go through the existing catch, so they print `measure: <message>` and exit 1.
   - Hint when `--key` is absent: if `comparePromptSizes` throws and `opts.key === undefined`, list the top-level keys of either file whose values are plain objects with `kind: 'prompt-size'` (pre's first, then post's new ones, no duplicates, in file order). If that list is non-empty, print `measure: <original message>; these files hold prompt-size sections, use --key <name>: <k1>, <k2>` and exit 1. If empty, print the original message unchanged. Do it in the CLI only. `comparePromptSizes` and its error text stay exactly as they are.
   - Leave the existing two-file argument check and its message (`compare requires two files: <pre.json> <post.json>`) unchanged.
3. USAGE (scripts/measure.mjs:15): `'       node scripts/measure.mjs compare [--key <name>] <pre.json> <post.json>'`.
4. Output: with `--key`, stdout is exactly what `comparePromptSizes(pre[key], post[key])` returns, as indented JSON (same `JSON.stringify(result, null, 2)`). No new fields, no wrapper object.
5. docs/ARCHITECTURE.md:91: after the existing sentence, add: `For combined files that keep several prompt-size results under named keys, such as .zc/baseline-pre.json, pass compare --key <name> to compare one section.` Format the file names and the command as code, matching the surrounding text.
6. CHANGELOG.md: under `## [Unreleased]`, before `### Changed`, add:
   ```
   ### Added

   - `scripts/measure.mjs compare --key <name>` compares one named prompt-size section of combined measurement files such as `.zc/baseline-pre.json`. Without `--key`, a combined file is still rejected, and the error now names the sections it holds.
   ```
