Objective: `acceptRun` must fail closed, staging nothing, when any path that is not the run's own already has a staged (index) change. A warning before an unrestricted `git commit` is not enough.

Decisions (final):
1. src/dispatch.mjs `acceptRun`: keep the existing computation of `alreadyStaged` (sorted subset of `leftAlone` whose status entry has `xy[0]` not ' ' and not '?'). Immediately after computing it and BEFORE the `git add` call: if `alreadyStaged.length`, throw `Error(\`cannot accept run ${prev.runId}: unrelated paths are already staged and would be committed with it: ${alreadyStaged.join(', ')}. Unstage them (git restore --staged -- <path>) or commit them separately, then run zc accept again.\`)`. Nothing is staged on this path. Remove `alreadyStaged` from the returned object (return `{ runId, staged, leftAlone }`) and update the JSDoc: returns `{ runId, staged, leftAlone }`; refuses when unrelated paths are staged; "Takes the same project lock as dispatch and reject." stays.
2. src/cli.mjs accept case: delete the `warning: already staged ...` line. Nothing else changes.
3. docs/ARCHITECTURE.md:
   - line ~79 "One lock for everything that changes the tree." bullet: `dispatch` and `reject` -> `dispatch`, `reject` and `accept` take the same project lock.
   - in the existing `zc accept` bullet, add one sentence: it also refuses, staging nothing, when files that are not the run's are already staged, so a following `git commit` contains only the run's files.
4. test/accept.test.mjs:
   - Replace the test at ~line 205 ("alreadyStaged lists an unrelated file ...") with: after an OK run writing worker files, the user stages an unrelated tracked file (modify README.md then `git add README.md`); record `before = git diff --cached --name-only` and `git diff --cached -- README.md`; `acceptRun` throws matching /unrelated paths are already staged.*README\.md/; afterwards `git diff --cached --name-only` equals `before` exactly (worker files NOT staged, README.md still staged) and `git diff --cached -- README.md` is unchanged.
   - Replace the CLI test at ~line 251 ("accept warns ...") with: same setup with an untracked `extra.txt` that the user stages; `node bin/zc.mjs accept <runId>` exits non-zero, its output (stdout+stderr) names `extra.txt`, and the index is unchanged.
   - The T-006 test at ~line 31 ("pre-existing staged change stays staged ...") stages README.md after the run, which is now refused: change it to assert the refusal and an unchanged index (same assertions as above) and keep its unstaged-modification check (the unstaged file stays unstaged). Do not weaken any other test.
   - Add: an unrelated UNSTAGED modification plus an unrelated untracked file (nothing staged) still lets accept succeed, staging exactly the run's files and leaving both untouched (unstaged stays unstaged, untracked stays untracked).
